# 多參加者共用手機集章：流程與規格草案

狀態：討論中，尚未進入開發

適用專案：Taiwan Wildlife Passport

文件目的：先確認多人共用同一瀏覽器時的操作流程與資料規則，再依定案規格開發。

開發順序說明：本功能排在新版集點卡與 7 枚印章替換、卡面姓名／留言／畫圖區定位完成之後，作為第三階段開發。

## 1. 背景

展場可能有多位小朋友共用家長的一支手機。現行系統在一個瀏覽器中只保存一張集章卡，因此：

- 第二位參加者必須等第一位完成並重置。
- 重置會刪除第一位的完成卡與留言。
- 直接開兩個瀏覽器分頁仍會共用同一份 `localStorage`，可能互相覆蓋。

本功能要讓同一瀏覽器保存多張獨立集章卡，並在掃描後清楚決定印章要加入哪一張卡。

## 2. 目標

- 一支手機可同時保存多位參加者的進度。
- 每位參加者有獨立的暱稱、7 枚印章、卡片樣式、留言與完成日期。
- 同一枚章在同一張卡中只能取得一次。
- 不同參加者可以取得相同的章。
- 支援手機內建相機開啟 QR 網址，也支援網站內建掃描器。
- 不要求登入、不辨識實體手機、不新增後端。
- 保留目前可離線使用與 GitHub Pages 靜態部署的特性。

## 3. 非目標

- 不限制同一支手機只能參加一次。
- 不保證一個暱稱等於一位真實人物。
- 不防止使用者建立多張卡或轉傳固定 QR Code。
- 不進行跨手機同步。
- 不建立帳號、會員、電話驗證或裝置指紋。

## 4. 建議的主要流程

### 4.1 第一次使用

1. 使用者開啟網站。
2. 顯示活動介紹與「新增參加者」。
3. 輸入第一位參加者暱稱並選擇卡片。
4. 建立第一張卡，進入該參加者的集章頁。

### 4.2 新增第二位參加者

1. 在集章頁點選上方的參加者切換器。
2. 點選「新增參加者」。
3. 輸入暱稱並選擇卡片。
4. 建立後切換到新卡；原卡進度完整保留。

### 4.3 平常切換卡片

頁面頂部顯示目前參加者，例如：

```text
目前：哥哥（3/7） ▾
```

打開後列出：

```text
✓ 哥哥  3/7
  妹妹  2/7
＋新增參加者
管理參加者
```

切換只改變目前畫面，不修改任何人的集章紀錄。

### 4.4 使用網站內建掃描器

1. 使用者先進入某位參加者的卡片。
2. 點選「掃描 QR Code」。
3. 掃描成功後，畫面顯示站點與目前參加者。
4. 使用者確認「蓋給哥哥」。
5. 印章加入哥哥的卡片。

建議即使已選擇參加者，仍顯示一次簡短確認，降低家長切錯卡的機率。

### 4.5 使用手機內建相機掃描

手機相機通常會另開新分頁，且不一定知道原分頁正在操作哪位參加者。因此：

- 只有一張未完成卡：直接顯示該參加者並要求確認。
- 有兩張以上卡：先顯示「這枚章要蓋給誰？」。
- 已擁有該章者仍列出，但標示「已取得」並不可重複加入。
- 所有人都已有該章：顯示「這支手機中的所有參加者都已取得此章」。

### 4.6 同一站要蓋給多位小朋友

建議預設流程：

1. 掃描一次站點 QR。
2. 選擇一位參加者並完成蓋章。
3. 結果頁提供「也蓋給另一位」。
4. 只列出尚未取得該章的參加者。
5. 每次仍需逐一確認。

這能讓同行小朋友共用手機，不必重複開啟相機，同時避免不小心一次替所有卡片加章。

### 4.7 完成與兌獎

- 每張卡依活動設定的印章總數判定完成；新版預計為 7/7。
- 完成後只進入該參加者的留言與輸出流程。
- 其他參加者不受影響，可繼續集章。
- 回到參加者清單時，完成者顯示「已完成」及完成日期。
- 低價獎品由工作人員查看指定參加者的完成畫面即可。

## 5. 分頁與狀態規則

### 5.1 不使用全域 active participant

若兩個瀏覽器分頁共用同一個 `activeParticipantId`，在 A 分頁切換參加者會連帶改變 B 分頁，容易蓋錯。

建議：

- 所有參加者資料保存在共用的 `localStorage`。
- 每個分頁目前顯示的 `participantId` 放在 URL 或 `sessionStorage`。
- 建議 URL 形式為 `?participant=<id>`，重新整理後仍可回到同一張卡。
- QR 站點網址不綁定參加者；掃描後由本機選擇歸屬。

### 5.2 多分頁同步

- 寫入前先重新讀取最新的共用資料。
- 一次只更新指定參加者，不以舊快照覆蓋整份資料。
- 監聽瀏覽器 `storage` 事件，其他分頁更新時同步畫面。
- 同一參加者若在兩個分頁同時取得不同章，兩筆紀錄都必須保留。

## 6. 建議資料結構

儲存版本由 `v1` 升級為 `v2`：

```js
{
  version: 2,
  participants: [
    {
      id: "random-uuid",
      nickname: "哥哥",
      language: "zh-TW",
      cardDesignId: "card-01",
      stamps: ["animal01", "animal03"],
      handwriting: "",
      textMessage: "",
      completedAt: "",
      createdAt: "ISO timestamp",
      updatedAt: "ISO timestamp"
    }
  ],
  lastUsedParticipantId: "random-uuid",
  updatedAt: "ISO timestamp"
}
```

規則：

- `id` 使用 `crypto.randomUUID()`，不用暱稱當識別碼。
- 暱稱可以重複，但介面應提示避免混淆。
- 每位參加者的 `stamps` 自動去除重複值。
- 建議同一瀏覽器最多保存 6 位參加者。
- 超過上限時，引導使用者刪除不需要的卡或匯出備份。

## 7. 舊資料遷移

第一次讀取新版程式時：

1. 若找到現有 `taiwan-wildlife-passport-v1`，將其轉成第一位參加者。
2. 保留原暱稱、印章、卡片、留言、手寫圖與完成日期。
3. 成功寫入 v2 後保留一份 v1 備援，直到使用者完成一次正常操作。
4. 遷移失敗時不可清除舊資料，並顯示可理解的錯誤。

## 8. 參加者管理

一般使用者可：

- 新增參加者。
- 修改暱稱。
- 切換參加者。
- 匯出全部進度。
- 刪除單一參加者，但需二次確認。

工作人員模式可：

- 查看所有參加者與各自進度。
- 對指定參加者補發或移除印章。
- 清除指定參加者的留言。
- 重置或刪除指定參加者。
- 匯入／匯出整支手機的全部資料。

## 9. 例外情境

| 情境 | 預期行為 |
|---|---|
| 只有一位參加者掃碼 | 顯示姓名並確認後加章 |
| 多位參加者掃碼 | 先選擇印章歸屬 |
| 選到已有該章者 | 顯示已取得，不重複新增 |
| QR 無效或 token 錯誤 | 不顯示參加者清單，直接顯示無效連結 |
| 某位剛好取得第六章 | 只將該位帶入完成流程 |
| 另一分頁同時更新 | 合併最新進度，不覆蓋其他人的紀錄 |
| 刪除目前參加者 | 切換到最近使用的其他卡；若沒有則回到新增頁 |
| 使用無痕模式 | 明確提示關閉分頁後資料可能消失 |
| 清除瀏覽器資料 | 資料無法復原，除非先匯出備份 |

## 10. 介面文字草案

- 新增參加者
- 切換參加者
- 管理參加者
- 這枚「臺灣黑熊」印章要蓋給誰？
- 蓋給哥哥
- 哥哥已經取得這枚章
- 也蓋給另一位
- 這支手機中的所有參加者都已取得此章
- 最多可建立 6 位參加者
- 刪除「哥哥」的集章卡？
- 這會刪除他的印章與留言，且無法復原

上述文字需同步提供英文、日文與繁體中文。

## 11. 待確認的重要決策

| 編號 | 問題 | 建議預設 |
|---|---|---|
| D1 | 一支手機最多幾位參加者？ | 6 位 |
| D2 | 掃描一次能否連續替多人蓋同一章？ | 可以，但每位逐一確認 |
| D3 | 內建掃描器是否也要確認姓名？ | 要，避免蓋錯 |
| D4 | 允許使用者自行刪除卡片嗎？ | 允許，二次確認 |
| D5 | 允許相同暱稱嗎？ | 允許，但顯示提醒 |
| D6 | 匯出檔包含一人還是全部？ | 預設匯出全部 |
| D7 | 完成者是否仍留在快速切換清單？ | 保留並標示已完成 |
| D8 | 是否真的支援兩個瀏覽器分頁各自固定一人？ | 支援，以 participant URL 區分 |

## 12. 驗收標準

- 可建立至少兩位參加者並獨立顯示進度。
- 兩位參加者可取得同一站印章。
- 同一參加者無法重複取得同一站印章。
- 掃 QR 後不會在未確認歸屬時直接加章。
- 兩個分頁分別顯示不同參加者時，切換其中一頁不影響另一頁。
- 兩個分頁同時寫入不同進度時不遺失資料。
- 現有 v1 使用者升級後進度完整保留。
- 刪除其中一位不影響其他參加者。
- 每位參加者集滿新版 7 枚印章後，可分別完成、留言及輸出 PNG。
- 工作人員操作必須明確指定參加者。
- 英文、日文、繁體中文流程均完整。
- 自動測試、production build 與既有單人流程全部通過。

## 13. 建議開發順序

1. 將 state model 升級為 v2，完成 v1 遷移與測試。
2. 加入參加者建立、切換、修改與刪除。
3. 改造掃碼歸屬選擇與「也蓋給另一位」。
4. 改造完成頁、工作人員模式與匯入／匯出。
5. 加入多分頁同步與競態測試。
6. 補齊三語文字、手機版操作與真機 QR 測試。
